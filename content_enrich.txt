Yes. If you want to scrape content/data from several websites, there are a few approaches depending on how those sites work.

1. Simple/static websites

If the data is present directly in the HTML, Python is usually enough:

import requests
from bs4 import BeautifulSoup


url = "https://example.com"


response = requests.get(
    url,
    headers={"User-Agent": "Mozilla/5.0"},
    timeout=20
)


soup = BeautifulSoup(response.text, "html.parser")


# Example: get all headings
for heading in soup.find_all("h2"):
    print(heading.get_text(" ", strip=True))

You can extract things like:

Product names
Prices
Articles
Headings
Tables
Links
Images
Metadata
2. JavaScript-heavy websites

If the content only appears after the page loads, requests + BeautifulSoup may not see it.

In that case, use Playwright:

pip install playwright
playwright install
from playwright.sync_api import sync_playwright


with sync_playwright() as p:
    browser = p.chromium.launch(headless=True)
    page = browser.new_page()


    page.goto("https://example.com", wait_until="networkidle")


    content = page.locator("body").inner_text()


    print(content)


    browser.close()

This is useful for sites that render content with React, Vue, Next.js, etc.

3. If the website has an API

An API is usually the best option. Instead of scraping the displayed webpage, you request the site's structured data directly.

For example:

import requests


response = requests.get(
    "https://example.com/api/products",
    params={"page": 1},
    timeout=20
)


data = response.json()


for product in data["products"]:
    print(product["name"], product["price"])

This is generally more reliable than scraping HTML.

4. For several websites

I would build it as separate "scrapers":

scraper/
├── main.py
├── sites/
│   ├── site_a.py
│   ├── site_b.py
│   └── site_c.py
├── output/
│   └── data.json
└── requirements.txt

Each site can have its own extraction logic, while main.py runs all of them and stores the results in JSON/CSV/database.

is there any other way to get the data in using the free tools or API

Yes. You don't necessarily need to build a scraper from scratch. There are several free/low-cost APIs and tools that can fetch website content for you.

Best options
Tool	Free option	Best for
Jina Reader	✅ Free basic usage	Getting clean text/Markdown from URLs
Firecrawl	✅ 1,000 pages/month currently	Scraping/crawling many pages
Apify	✅ $5/month platform usage	More advanced scrapers/actors
Website API	Often free	Structured data directly from the source
RSS / Sitemap	Usually free	Articles, blogs, news, product catalogs
1. Jina Reader — probably the easiest

Jina Reader API

You can essentially give it:

https://r.jina.ai/https://example.com/article

and get the webpage converted into clean text/Markdown.

Jina currently allows basic Reader usage without an API key, with a published limit of 20 requests/minute; a free API key increases the Reader limit to 500 requests/minute.

You can also ask it to extract structured fields such as:

{
  "title": "...",
  "author": "...",
  "date": "...",
  "price": "...",
  "description": "..."
}

That can be very useful if you're collecting the same type of information from many websites.

2. Firecrawl — better for crawling whole websites

Firecrawl

Firecrawl is particularly interesting if you have:

website.com
   ↓
find pages
   ↓
crawl pages
   ↓
extract content
   ↓
JSON / Markdown

Its current free API allowance is 1,000 pages/month. Scrape, crawl, map and monitor operations generally consume one credit per page.

They also have free browser-based extraction tools that don't require signup.

3. Apify

Apify

This is useful if you want something more like a scraping platform rather than just an API.

They have ready-made "Actors" for different websites and scraping tasks. Their free plan currently includes $5/month of platform usage, with no credit card required.

But there's an even better approach

Before scraping a website, check whether it has:

Website → API → RSS → Sitemap → HTML → Browser automation

in that order.

For example, suppose you want data from 10 websites:

Website A → official API       ✅
Website B → RSS feed           ✅
Website C → sitemap + HTML     ✅
Website D → Jina Reader        ✅
Website E → Firecrawl          ✅
Website F → JavaScript         → Playwright

This is much more reliable than trying to scrape everything the same way.

If your goal is large-scale data collection

If you're planning something like:

"I have 20 websites and want to collect 50,000+ pages, extract specific fields, and put everything into Excel/CSV/SQL."

I'd recommend building:

             ┌── Website 1
             ├── Website 2
URLs ────────┼── Website 3
             └── Website N
                  ↓
           Fetch / Crawl
                  ↓
        Content Extraction
                  ↓
        Structured JSON
                  ↓
       PostgreSQL / CSV

And you can combine Jina + Firecrawl + Python to keep the cost very low.
